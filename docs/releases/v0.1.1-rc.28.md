# Xray Pilot v0.1.1-rc.28

Windows x64 本地验证版，在 `v0.1.1-rc.27`（本地时区日志时间戳）的基础上，支持在主动退出程序后，下次启动时自动恢复退出前的代理连接方式（如 PAC 自动代理、全局代理或直连）。**本版尚未发布到 GitHub Release**。

## 本次变化

- **退出前代理连接方式自动恢复（`crates/xray-manager-app`）**：
  - 在 `Workspace`（`gui.json`）中新增持久化字段 `last_proxy_mode`（默认 `Direct`）与 `last_pac`（最近一次成功应用的 `PacDraft`），仅记录真实已提交/已运行的应用状态，未点击应用的界面草稿改动不会误覆盖上次生效配置；
  - 主动退出程序（`ExitKind::Shutdown`）向后台发送 `Command::Shutdown` 停止 Core 并干净释放系统代理前，保留并持久化退出前正在使用的连接方式与已应用 PAC 规则；后台状态轮询看到 `Stopped` 时不会误清除恢复意图；
  - 下次启动执行 `maybe_restore_core()` 且开启“启动时恢复上次 Core 运行状态”时：若退出前为 `Pac`，自动派发 `Command::SetProxyMode` 重新编译并启动 Core + PAC 服务与系统代理；若退出前为 `Global`，自动恢复全局系统代理与 Core；若为 `Direct`，保持通过 `Command::RestartCore` 恢复直连运行；
  - 显式点击 **停止 Core** 仍清除 `last_core_running`，手动停止后下次启动保持停止状态，且仍禁止在 Core 未运行时于界面手动直接切换代理模式。
- **文案与测试更新**：
  - 更新 **设置 → 启动行为** 与 `docs/validation-guide.md` 说明，明确启动恢复涵盖运行状态与退出前系统代理连接方式；
  - 新增回归测试 `pac_proxy_mode_is_persisted_across_shutdown_and_restored_on_startup` 与 `global_proxy_mode_is_restored_on_startup_while_manual_stopped_switch_stays_blocked`。

## 验证

在构建打包前执行 `cargo update --workspace`、Linux 全工作区 `cargo test --workspace --locked`、Linux 与 `x86_64-pc-windows-gnu` 双目标严格 Clippy、`cargo fmt --all -- --check`、`git diff --check` 以及 Windows x64 交叉编译与包校验。
