# Xray Pilot v0.1.1-rc.17

Windows x64 本地验证版，修复重启/登录后自动连接因依赖不完整而报错并阻断后台的问题。**本版尚未发布到 GitHub Release**。

## 根因与修复

- 上次运行配置包含未分类字段或动态外部依赖时，`resources.complete=false`。启动时 `connect_on_start` 直接返回 `RESOURCE_REVALIDATION_REQUIRED`，导致：
  - 界面显示红色错误；
  - Supervisor 被标记为 blocked；
  - 用户无法正常手动启动。
- 现在按依赖类型处理：
  - **仅未分类字段**：仍尝试自动启动；成功后 Core 正常运行，并显示“自动恢复不可用”的非致命提示；失败也只显示提示，不再阻断；
  - **动态外部依赖**：无法在启动前保证内容，跳过自动连接并提示手动启动；
  - 两种情况都不再把 Supervisor 标记为 blocked，也不再显示红色 `RESOURCE_REVALIDATION_REQUIRED`。
- 应用层自动恢复同步调整：未分类字段可尝试启动，动态依赖跳过。
- 设置页说明：包含动态外部依赖时会跳过自动连接；未分类字段会尝试启动，但自动恢复不可用。
- **PAC 测试 URL**：输入 `example.com` 会自动补全为 `https://example.com`；空值、相对路径和非 HTTP(S) 地址在界面侧直接提示，不再发送后才出现 `PAC_URL_INVALID`。

## 验证

新增“依赖不完整时跳过自动连接但不阻断、可手动启动”的回归。全工作区 **208 项**常规回归通过，7 项需显式环境用例忽略；Linux/Windows GNU 严格 Clippy、fmt 通过。

## 说明

自动恢复仍要求完整冻结依赖；如需每次重启自动启动，请在配置预览中处理“资源与自动恢复限制”，避免未分类字段或动态外部依赖，或接受手动启动。
