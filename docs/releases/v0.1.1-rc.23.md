# Xray Pilot v0.1.1-rc.23

Windows x64 本地验证版，在 `v0.1.1-rc.22` 的基础上修复开机自启冷启动时界面工作线程与后台 Supervisor IPC 管道就绪之间的竞态导致的 `CONNECTION_LOST: IO_ERROR: 系统找不到指定的文件。 (os error 2)` 启动报错。**本版尚未发布到 GitHub Release**。

## 本次变化

- **开机自启服务就绪等待与无错启动**：
  - `Supervisor` 拆分为 `prepare`（获取目录锁与初始化基础状态）和 `finish_open`（启动恢复与 `connect_on_start`）：`ipc::serve` 在获取目录锁后立即创建命名管道 / Unix 套接字并并发接收请求，不再等到 Core 验证/启动/就绪握手全部结束后才暴露管道，从源头避免冷启动期 `os error 2`；
  - `xray-manager` 工作线程启动逻辑重构为按进程存活检测的 `ensure_supervisor_ready`（最长等待 30 秒，若子进程异常退出则经 3 秒宽限期快速结束避免死等），在后台服务真正就绪后再派发初始化查询队列；`GetStatus` 遇到 `IO_ERROR` 断开时自动重连等待并重试一次只读查询（写操作仍严禁自动重放）；
  - 区分写操作与只读状态查询的 `CONNECTION_LOST` / `IPC_TIMEOUT` 提示文案，只读轮询/启动失败不再误提示“后台响应中断，请先查询原操作结果，再进行其他变更。”。
- **包含 v0.1.1-rc.22 全部改进**：
  - 外部系统代理冲突（`PROXY_LEASE_CONFLICT`）WinINet 快照对比诊断、`ResolveProxyConflict` 显式确认解除（保留外部设置）、原始恢复错误保留与纯代理冲突恢复期间允许修改/保存开机自启设置。

## 验证

全工作区 **227 项**常规回归通过，7 项需显式环境用例忽略（包含 `xray-supervisor` 启动恢复期间 IPC 并发接入回归与 `xray-manager-app` 后台服务就绪检测及读写断连提示回归）；`cargo fmt --check`、Linux 与 `x86_64-pc-windows-gnu` 双目标严格 Clippy、`git diff --check` 全部通过。

真实 Windows 开机冷登录自动启动（含 Core 自启恢复期间打开界面及 `--background` 驻留托盘）、`PROXY_LEASE_CONFLICT` 冲突解除及取消自启仍需按验证指南实机验收。
