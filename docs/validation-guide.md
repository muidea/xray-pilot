# 验证说明

本包为 **v0.1.1-rc.17 Windows x64 本地验证版**，包含 PAC 自动代理与内置模板、持久化日志、WinHTTP 只读诊断、Dynamic 依赖、Mixed 入站、路由冲突提示和 TCP 延迟探测。构建版本、源码提交和文件指纹见 `VERSION.txt` 与 `SOURCE-MANIFEST.json`；本地验证包可能记录 `source_dirty=true`，不能作为已发布版本。

文件名统一采用 `xray-pilot-<版本>-windows-x64.zip`，验证版本使用 `rc.N` 预发布版本号。每轮内容不同的对外交付使用新的版本号。本包由 Linux 交叉构建 Windows GNU 目标，用于功能验证；正式发布前仍需 MSVC CI 和签核。验证包只附带本说明和 `docs/发布说明.md`，设计、评审、交接和历史收口文档保留在源码仓库，不随验证包分发。

## 1. 准备

1. 完整解压到一个新的可写目录，例如 `D:\Apps\xray-pilot`。
2. 若更新已有安装，先通过“退出程序（停止 Core 并恢复代理）”完全退出旧后台，备份 data，再同时替换三个 exe。不要让新界面连接仍在运行的旧版后台。
3. 双击 `xray-manager.exe`，按首次设置向导准备官方依赖、添加配置、检查并确认启动。默认数据目录为解压后的 `xray-pilot\data`。

本包不包含 Xray Core；自动部署从 XTLS/Xray-core 官方发布页获取并校验。离线准备、配置示例及详细操作见 `README.md`。

## 2. PAC 验证

1. 在 **配置 → 本地入口** 确认存在回环、无认证的 `http` 或 `mixed` 入站。
2. 打开 **PAC** 页，确认显示 **内置默认模板** 和当前 HTTP/Mixed 代理目标。
3. 选择 **代理范围**：
   - **全部代理（本地/局域网直连）**：清单不生效。
   - **仅代理清单中的域名**：只有清单域名进入 Xray，其余直连。
   - **清单中的域名直连，其余代理**：清单域名直连，其余进入 Xray。
4. 在“添加域名”输入 `example.com`、`*.example.com` 或 `full:example.com`，点击 **添加**；清单项可逐项 **移除**。添加/移除会立即保存草稿，并强制切回内置模板（即使此前使用自定义或自动生成脚本）。
5. 点击步骤 3 的 **生成并检查模板**，再在步骤 4 点击 **测试当前模板**；确认清单内外的域名分别返回 PROXY / DIRECT，且 `localhost`、纯主机名和 `.lan`/`.local` 始终 DIRECT。
6. 在步骤 5 点击 **检查并预览 PAC 应用**；确认预览中的代理方式为 PAC、脚本为“内置模板（仅代理清单）”，再点击确认应用。也可回配置页重新检查并应用。PAC 页应显示新的 PAC URL。
7. 可在 PowerShell 中读取当前 PAC：

```powershell
Invoke-WebRequest -UseBasicParsing '<PAC URL>' | Select-Object -ExpandProperty Content
```

8. 验证释放：点击 **停止 Core** 或 **退出程序（停止 Core 并恢复代理）**，确认系统代理恢复到测试前设置。

建议在受控测试前后记录当前用户 WinINet 四项设置：

```powershell
.\scripts\windows-proxy-snapshot.ps1 -Save .\proxy-before.json
# 执行 PAC / Global / Direct 测试
.\scripts\windows-proxy-snapshot.ps1 -Compare .\proxy-before.json
```

脚本只读注册表，不写代理设置。测试前请保存原代理设置并避免在生产账户上执行。

## 3. 启动恢复验证

1. 在 **设置 → 启动行为** 确认 **启动时恢复上次 Core 运行状态** 默认开启。
2. 启动 Core 后选择 **退出程序（停止 Core 并恢复代理）**；确认 Core 停止、代理恢复。
3. 再次启动 `xray-manager.exe`；连接后台后应自动启动上次已应用版本，总览显示 **Core 运行中**。
4. 显式点击 **停止 Core**，完全退出后再次启动；不应自动启动 Core。
5. 取消勾选“启动时恢复”，重复第 2–3 步；不应自动启动。
6. 自动恢复只启动 Core，不自动重新接管系统代理；需要时手动选择 Global/PAC。
7. 若配置包含未分类字段，自动启动会尝试运行并提示自动恢复不可用；若包含动态外部依赖，自动连接会跳过。两种情况都不应阻断后台，可手动点击“启动上次应用版本”。

## 4. 诊断与对话框验证

- **配置历史**：选择 **比较并载入…**，确认先显示差异对话框，取消不会改变当前草稿，确认后才载入；载入后仍需检查并应用。
- **诊断数据**：检查 Core 进程、代理归属、代理模式、恢复状态、本地入口探针、PAC 服务、WinHTTP 会话代理和最近错误。WinHTTP 只看当前 WinHTTP 默认会话，不修改机器级设置；路由静态预测只核对规则与出站，不发起连接。
- **WinHTTP**：显示 WinHTTP 默认会话的访问类型、代理和绕过；不使用“机器级 WinHTTP”表述，不修改设置。
- **TCP 延迟**：输入主机和端口，确认显示目标地址与毫秒数；它只测量 TCP 握手，不经过 Xray。
- **路由预测**：静态预测仅用于当前运行配置；实际出口仍需外部验证。
- **对话框**：逐一打开新建/导入、重命名、确认应用、停止/重启、删除、未保存退出、退出确认和应用预览；确认标题、说明、滚动区域和按钮行位置一致，长内容不遮挡按钮。
- **托盘退出**：托盘只有一个 **退出…** 项；打开后默认选中“仅退出界面”，可切换到“退出整个程序”，勾选“记住为默认退出方式”后下次应预选该选项。分别验证两种退出方式。
- **首次向导**：在设置向导第一步确认 **保存并继续** 与 **稍后设置，进入总览** 位于同一水平行。
- **PAC 空配置**：在没有添加/选择配置时打开 PAC 页，应显示“尚未选择配置”提示，不应出现 JSON EOF 解析错误。
- **Mixed 入站**：创建 `protocol: "mixed"` 入站后启动，确认本地入口状态为就绪；Global/PAC 可选择该入口。
- **日志**：在设置 → 数据与存储查看 `logs/supervisor.log`；确认带时间戳、请求/代次上下文，密码/UUID 等字段脱敏，重启后仍能看到最近日志。
- **Dynamic 依赖**：配置绝对外部文件时勾选“允许动态外部依赖路径”；应用/启动前修改文件应报告 `RESOURCE_REVALIDATION_REQUIRED`，自动连接和自动恢复不可用。
- **撤销/重做**：编辑配置后使用“撤销编辑 / 重做”，确认草稿、候选和预览状态同步失效并重新检查。
- **导出提示**：导出 JSON 前应提示地址、UUID、密码、私钥等敏感内容风险。

## 5. 已知边界

- 真实 WinINet 四项设置往返、企业 PAC / 外部代理竞争、连续切换和异常释放仍需在干净 Windows 账户中验证（V01）。
- 真实 Windows PAC URL 往返、浏览器/客户端缓存差异、公网出口、完整 JScript 兼容和双向原生规则合并仍需验证（V10）。
- PAC 执行环境有循环/递归/栈/大小限制，但不是完整内存隔离；`dnsResolve`、`isInNet` 等网络辅助函数返回 Unsupported。
- PAC 服务由 Supervisor 持有：强制结束 Supervisor 后 PAC URL 可能不可达。PAC 目标同时设置 `AUTO_PROXY_URL` 和 `DIRECT` 位，确保脚本返回的 `DIRECT` 生效；PAC 不可达时的 WinINet 回退行为必须实测。
- PAC 语法检查使用 Boa（ES2020 子集），Windows WinINet 使用 JScript；`let`/`const`/箭头函数等会显示兼容性提示，应以 Windows 客户端为准。
- F01 历史 / 详情过期、自动维护、依赖缓存清理和容量上限尚未实现；F02/F03/F05 高级组合、语义级撤销和订阅能力仍保留。
- 真实注销/登录、跨 SID、磁盘满、安全软件、断电、完整桌面交互、远端 CI / MSVC / 正式发布包仍需按源码仓库的遗留清单验收。

自动回归与隔离 Windows 冒烟记录保留在源码仓库，不随验证包分发。校验下载文件可使用 PowerShell `Get-FileHash`，与包外 `SHA256SUMS` 比较。
