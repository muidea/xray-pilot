# 配置交互实现与验证

状态：2026-11-11，按用户确认方案完成当前源码实现。此变更尚未包含在已发布的 v0.1.1-rc.4 包中。

## 使用流程

1. 配置 → 新建，填写显示名称，选择单节点代理、按网站分流或本地直连诊断。
2. 选择与服务端一致的协议模板，点击开始填写。按资料补充地址、端口、认证与必要的安全参数；可先保存待补充配置。
3. 在节点页管理节点、显示名称及默认访问方式；在分流规则页选择匹配内容与处理目标。
4. 概览展示缺项提示，点击去补充定位表单。可选择及增删多个服务器 / 用户；格式异常与复杂原生字段使用高级编辑或原始 JSON。
5. 单独选择是否接管 Windows 系统代理；需要接管时通过列表选择本地 HTTP 入口。
6. 检查并预览，核对默认访问、本地入口、规则数量、代理方式、资源限制与差异，明确确认后应用。

## 模板与字段

| 模板 | 连接输入 | 按需展开 |
| --- | --- | --- |
| VLESS + Reality | 地址、端口、用户 ID / UUID、SNI、公钥、客户端指纹 | Short ID、Flow、传输参数 |
| VLESS + TLS | 地址、端口、用户 ID / UUID | SNI、Flow、WebSocket / gRPC |
| Trojan + TLS | 地址、端口、密码 | SNI、WebSocket / gRPC |
| Shadowsocks | 地址、端口、加密方式、密码 | 原生安全与传输字段 |
| SOCKS / HTTP 上游 | 地址、端口 | 账号密码认证、安全与传输 |
| VMess（兼容） | 地址、端口、用户 ID / UUID | 加密、安全与传输 |

模板准备 `127.0.0.1:10808` SOCKS 与 `127.0.0.1:10809` HTTP 入口、唯一内部 Tag、直连 / 阻止出站和空规则列表。远端地址、端口、密码、用户 ID、公钥及服务端名称均不生成。端口冲突沿用现有检查 / 应用保护，不静默更换监听端口。分流模板默认经过所填节点，不写入影响真实网站的示例规则。

加密方式、指纹及 Flow 提供常用值菜单，允许手动输入。认证默认隐藏，可主动显示；新的创建会话重置显示状态。TLS 不提供自动关闭证书验证的绕过方式；导入配置已有 `allowInsecure: true` 时保留并提示，允许明确恢复验证。Reality 兼容原生 `publicKey` / `password` 字段写法。

## 编辑与保留合同

- 既有配置仅修补用户编辑的 JSON 路径，缺失对象 / 首个数组条目可按需补充；类型异常的父字段拒绝覆盖。未知字段、其他服务器 / 用户、其他出站与规则顺序保留。
- 节点名称位于 `data/config/gui.json` 的 `node_names[profile_id][tag]`，不进入 Xray 配置。复制配置携带名称；删除配置清理对应名称。常用表单不修改 Tag，避免引用失效；自动新增节点也避开已保留名称的旧 Tag。
- 默认方式完整移动所选出站到首项，其余出站保持相对顺序；不重建节点或修改规则。删除默认节点前需换选，被路由、链式出站或其他原生字段引用时拒绝常用表单删除。
- 常用路由仅编辑简单单条件规则。网站表单把裸域名转为 `domain:`，保留 `full:` / `regexp:` / `geosite:` 等原生前缀。导入的裸子串规则与带额外字段的组合规则保留在高级编辑，避免语义被转换。
- 路由提供网站 / IP 类型、节点名称选择、顺序调整与删除；提示空匹配项及相同匹配条件。它不是完整冲突分析，也不是网络可达性测试。
- 无效端口文本直接保留在配置草稿，修正为整数后清除提示。高级原生数值编辑把负号、小数点等未完成输入绑定到原 JSON 数值和路径，随草稿持久保存；数值有效后才更新 JSON。补全前阻止检查应用、复制 / 导出配置、原始 JSON 修改和结构删除 / 排序，提供定位入口；保存失败沿用退出阻断与导出未保存草稿。高级对象支持增删字段及新增字段类型选择。
- 配置与节点表单、原始 JSON 共用当前草稿。操作继续经过原候选上下文、Core 校验、资源冻结、预览与确认应用合同。查看表单不会创建缺失字段或改变运行快照。

## 布局

名称与配置操作合并为可换行区域，移除重复的内部标识 / 草稿说明。常用表单与高级编辑在内容顶部切换；默认访问方式同排选择。节点与路由在父容器剩余空间滚动，底部检查操作独立保留。新建窗口的标题、取消及保存操作位于滚动区外。深浅主题覆盖 760×500、1100×760、1920×1040 的页面检查，以及全部模板的创建窗口。

## 验证与边界

回归覆盖所有模板的缺项保存、缺项跳转和字段修复、无效端口逐帧输入、未知字段 / 其他用户保留、默认节点与引用删除保护、域名匹配语义、认证显示隔离、名称持久化、原生数值缓冲、只读展示不产生写入，以及主题 / 尺寸 / 长内容布局。原有候选、草稿持久化、预览确认与运行版本回归继续执行。

官方 Core 专项通过 `XRAY_TEST_CORE` 显式指定已校验的官方程序，对填写测试参数后的七种模板及 VLESS / Trojan 的 WebSocket、gRPC 组合执行 `run -test`。该专项不启动代理服务，不修改系统代理，也不证明远端网络可达。
