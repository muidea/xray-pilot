## 草稿、候选和运行快照

选择配置仅切换编辑对象，编辑、格式化、排序、复制及载入历史都不直接应用。原生 JSON 的未知字段由既有编辑器保留。历史先载入草稿，再使用当前 Core 重新检查，不直接应用旧候选。

检查成功后打开预览，展示当前运行 JSON、待应用 JSON、相对已保存配置的差异、实际 Core 身份及冻结资源说明，用户明确确认才应用。候选绑定配置、Revision、草稿、编辑代次、Core、资源、代理上下文及后台 / 运行代次；编辑后再改回原值也须重新检查。应用响应按提交时捕获的配置结算，不覆盖期间切换到的其他编辑对象。

草稿静置 800 ms 后持久保存，切换与正常退出也会保存。恢复时若基准 Revision 已变化，用户须明确选择保留草稿内容或放弃草稿；保留后仍须重新检查。无法读取的本地资料与草稿文件不被隐式覆盖。

| 数据目录内路径 | 内容与边界 |
| --- | --- |
| `config/gui.json` | `names` 保存配置 ID 到显示名称的映射；`asset_roots` 保存 Core 路径到资源来源目录的映射 |
| `config/editor-drafts/<id>.json` | `base_revision` 与未应用的 `json`；ID 使用既有合法性检查，禁止目录穿越 |
| `config/appearance.json` | 沿用既有外观偏好存储，三种主题立即生效并保存 |

这些资料与正式 Profile、活动清单及恢复证据分离。新增配置采用自动生成的内部 ID，中文名称只保存在 GUI 资料中。草稿同样可能包含认证信息，应纳入数据目录备份和访问保护。

现有后台禁止删除被当前提交清单引用的配置，即使 Core 已停止。界面据此禁用删除并提示先应用另一份配置；本轮不修改此恢复合同。未提供运行中数据目录迁移，也未扩展 PAC、TUN 或服务模式。

## 后台接口和异常处理

新增两个只读命令，协议版本保持 1，旧有 `TestRoute` 语义保留：

| 命令 | 合同 |
| --- | --- |
| `GetRuntimeConfig { generation_id }` | 仅读取当前提交代次的冻结 JSON，校验配置哈希并返回 `{ generation_id, json }`；代次不符或文件被改动时拒绝 |
| `TestRunningRoute { generation_id, context }` | 要求 Core 运行，使用同一冻结 JSON 执行既有静态预测；不读取可能已变化的 Profile，也不宣称实际出口已验证 |

断线保留最后已知状态并禁用写操作；重连后重新读取状态。写请求的传输失败标记为结果待确认，按原 request ID 查询，不自动重发。查询核对原操作及响应身份，非终态或缺失结果继续阻断冲突变更。后台恢复受限时保留查询和安全停止入口。

关闭窗口继续收起到 Windows 托盘；仅退出界面保留后台与 Core；完整退出等待在途写操作及结果确认，再停止后台、Core 并条件恢复代理。C17 的隐藏窗口唤醒机制保留，托盘启用状态随实际运行状态更新，代理切换使用运行版本的入站 Tag。

## 配置显示、原生 API 校验与待补充导入（2026-11-10）

## 编辑区域随父容器自适应（2026-11-10）

用户截图中最大化配置页的 JSON 只显示少数行，原因是编辑列以零高度分配，嵌套滚动内容又没有传递实际视口高度。现将主内容区的可用高度传递到配置列，先按实际内容排布标题、标签栏和底部操作区，JSON 编辑器占用剩余空间，不再固定 320 像素。入站、出站、路由、概览和历史的内容在剩余区域内滚动；窗口过小时保留最小编辑面积并允许页面滚动。

共享 JSON 组件的边框与背景绘制在视口而非文档上，短文档也填满父容器，空白区域可点击输入；长行保持横向滚动，长文档纵向滚动。导入根据中部表单剩余高度调整编辑区，应用预览采用同一组件的只读模式，左右两列等高并独立滚动。窗口尺寸变化不会改动草稿内容或触发应用。

## 预览长提示重叠与滚动隔离（2026-11-10）

用户后续截图暴露了上一轮自适应调整的边界：预览正文被限制为视口高度，长配置再叠加多条资源提示时，超出空间的行发生重叠。现只对滚动视口限高，正文保持自然高度；JSON 仍以显式视口预算计算高度。导入表单同步移除正文高度约束，避免大量补充提示发生同类问题。

资源覆盖不完整时，预览在 JSON 上方显示中文摘要：配置已通过 Core 校验，可以手动确认应用；管理器的自动连接、异常重试和旧 Core 自动恢复不可用。这是现有覆盖白名单的能力边界，不表示配置非法，也未放宽后台恢复限制。逐字段说明默认折叠、自动换行，在独立限高视口内滚动；已知英文覆盖提示转换为中文，持久化的原始诊断保持原值。标题和确认操作继续位于正文外部。

预览正文、JSON 滚动和限制详情的界面身份绑定候选 ID；新候选从顶部打开，不沿用旧候选滚动或展开状态。Linux GUI 44 项、Windows 原生 GUI 46 项全部通过，格式与两平台 GUI 全目标严格 Clippy 通过。新增正式回归在两种主题及 760×500、1100×760、1920×1040 下使用长 JSON、长字段路径和 40 条提示，通过实际指针展开和滚轮输入读到最后一项，逐次核对提示矩形不重叠、标题和确认按钮可见，并核对新候选从顶部展示中文摘要。

Windows 原生测试导出的图元及字体图集位于 Windows 用户临时目录 `xray-preview-validation-5a3s_20v/layout-captures`，仅包含合成配置。此类图元回归不替代全部 HWND 人工交互验收；C18–C20 与其他遗留状态继续保留。
